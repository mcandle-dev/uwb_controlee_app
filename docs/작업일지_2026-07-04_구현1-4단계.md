## 1단계 — 스캐폴드 + 매니페스트/권한/가용성 체크 (완료)

- Gradle 스캐폴드 생성, 매니페스트에 `uses-feature android.hardware.uwb (required=true)`
  + `UWB_RANGING` 권한 선언.
- **가용성 4-상태 진단 (FR-1)**: 하드웨어(`FEATURE_UWB`) → 권한 → 어댑터
  (`UwbManager.isAvailable()`) 순서로 판정. 미탑재/권한 거부/토글 OFF/사용 가능 구분.
  - `isAvailable()`이 core-uwb 1.0.0에 존재함을 빌드로 확인 (문서상 불확실했던 부분).
- 상태별 배너 + 액션: 권한 거부 → [권한 요청]/[앱 설정], 토글 OFF → [설정 열기]
  (`android.settings.UWB_SETTINGS` 시도, 없으면 무선 설정 폴백).
- 설정 갔다 돌아오는 경우 반영 위해 `onResume`마다 재판정.
- 로그 콘솔 기반 구축 (타임스탬프, 500줄 상한, 자동 스크롤 — FR-9/NFR-5).
- **실기기 검수: UWB Galaxy에서 READY 표시 확인됨.**

## 2단계 — controleeSessionScope + 내 주소 표시 (완료)

- READY 판정 즉시 `uwbManager.controleeSessionScope()` 자동 생성 →
  `localAddress`를 hex(예 `5F:DD`)로 카드에 크게 표시 (FR-3).
  Start 전에 PC 스크립트 `--dest-mac`에 입력해야 하므로 자동 발급이 요구사항.
- 탭 → 클립보드 복사 + 스낵바 + 로그. 미발급 상태는 `--:--`.
- UWB 사용 불가 전환 시 주소 무효화, onResume 중복 획득 가드, 발급 실패는
  로그만 남기고 크래시 없음 (NFR-2).
- **실기기 검수: 주소 `5F:DD` 표시 확인됨.**

## 3단계 — RangingParameters + Start/Stop + 측정 UI (완료)

- **Start** = `prepareSession(params)` Flow 수집 시작(= controlee 대기),
  **Stop** = Job 취소(= 세션 종료). 스코프는 세션 1회용이라 종료 때마다 재발급 —
  주소가 바뀌면 "내 주소 변경: A → B — PC에 다시 입력 필요" 로그 (FR-3 상세).
- 입력 검증 (FR-4): 보드 MAC `XX:XX`/`XXXX` hex 2바이트, Session ID 양의 정수.
  오류 시 빨간 안내문 + Start 비활성. 레인징 중 입력 비활성.
- 상태 머신 (FR-7): IDLE → WAITING(파랑) → RANGING(초록) → DISCONNECTED/ERROR(빨강),
  색상 배지. DISCONNECTED/ERROR에서 Start = 재시도.
- 측정 표시 (FR-6): 거리 cm(m→cm 환산, 0~5000 밖 주황), azimuth °(null=N/A),
  "마지막 갱신 X.Xs 전" 1초 갱신.
- 무수신 워치독 (FR-8): RANGING 중 2초 무측정 → 노란 "수신없음" 배지, 세션 유지,
  자동 재시작 없음 (증상 보존).
- 로그 (FR-9): 시작/정지/첫 측정/10건마다 평균 요약/끊김/수신없음 진입·해제/예외 원문.
- 수명주기 (NFR-3/4): `ProcessLifecycleOwner`로 앱 백그라운드 진입 시 세션 정지
  (화면 회전에는 반응 안 함 — ViewModel이 세션 소유라 회전 시 유지).
  `onCleared`에서 Job 취소로 좀비 세션 방지.
- **실기기 검수: Start→WAITING, Stop→IDLE, 입력 검증 동작 확인됨.**

## 4단계 — sasodoma 리포 파라미터 쌍 대조 (완료)

기준: https://github.com/sasodoma/uwb-ranging @ `aad72a0` (2025-05-28).
상세 대조표: `docs/파라미터_대조_4단계.md`.

**발견·수정한 불일치 2건 (+1):**

| 항목 | 수정 전 (placeholder) | 수정 후 (기준값) | 원인 |
|---|---|---|---|
| Static STS 키 | `08 07 06 05 04 03 02 01` | `08 07 01 02 03 04 05 06` | PC UCI가 리틀엔디언 정수 → IV 바이트 순서 반전 |
| 갱신 주기 | AUTOMATIC | FREQUENT (120ms) | PC `RANGING_DURATION=120`과 쌍 |
| 보드 MAC 기본값 | `00:01` | `00:00` | PC `--mac 00:00` 절차와 쌍 |

- 일치 확인: Config(DS-TWR deferred/unicast/SP3/time), Session ID 42, CH 9, PRE 9,
  static STS, sub-session 미사용.
- 앱에서 설정 불가한 값(slots/RR 6, hopping on, RSSI on)은 sasodoma가 PC 스크립트
  기본값을 미리 맞춰 둠 → **원본 Qorvo 스크립트가 아닌 sasodoma 사본 필수**.
- CLAUDE.md 세션 계약 표·코드 스니펫을 검증값으로 갱신.

## 현재 상태 요약

- 검수 기준(요구사항정의서 §7) **보드 없이 항목 1~4: 전부 통과** (실기기 확인).

- 미해결 리스크 (5단계에서 확인할 것):
  1. 주소/STS **바이트 순서** — 세션은 붙는데 조용히 측정이 안 나오면 1순위 의심.
  2. 갱신 주기 FREQUENT(120ms) 가정 — Galaxy 기종별 프로필 차이 가능성.
  3. sasodoma 검증 기기는 Pixel 8/9 Pro — Galaxy에서의 인터롭은 이번이 첫 확인.
