## 2. 준비물·설치

### 기기 3대

| 기기 | 역할 | 요구 사항 |
|---|---|---|
| 폰 ① | controlee 앱 (이 리포) | **UWB 지원 Galaxy** (측정 당사자) |
| 폰 ② | 콘솔 앱 | UWB 불필요. USB-OTG 가능 기종 |
| 보드 | DWM3001CDK | 폰 ② 에 USB-OTG 케이블로 연결 |

### 설치

1. controlee (폰 ①): 이 리포에서 `.\gradlew.bat assembleDebug` →
   `adb install -r app\build\outputs\apk\debug\app-debug.apk`
2. 콘솔 (폰 ②): 콘솔 리포에서 `.\gradlew.bat assembleHwDebug` →
   `app\build\outputs\apk\hw\debug\` 의 APK 설치.
   **반드시 hw flavor** — sim flavor 는 가짜 BLE/보드라 인터롭 검증이 안 된다.
3. 설치 확인: 폰 ② 앱 이름이 **"UWB Console 2"** 인지 확인. "UWB Console"(v1)은
   스캐너 모드만 있어 검수 10·12 를 진행할 수 없다. (v1/v2 는 동시 설치 가능 — 별개 앱)
4. 첫 실행 시 권한 요청(블루투스 근처 기기·알림)은 모두 허용. 콘솔에서 "광고 송출"
   선택 시 광고 권한 팝업이 한 번 더 뜬다 — 허용.

### 공통 조작 위치

- **콘솔 모드 선택**: 설정(⚙) → "OOB 교환 방식" → 스캐너 (v1) / 비컨 관찰 / 광고 송출
- **폰 모드 선택**: 메인 화면의 모드 선택 (모드 1 / 모드 2 / 모드 3)
- **콘솔 [OOB] 버튼**: BLE 교환 시작. 로그 창에 `[OOB]` 접두어로 진행 로그가 찍힌다
- 모드 변경은 **레인징 중이 아닐 때만** — Stop 후 변경할 것

### 검수 11 — 모드 1 회귀 (가장 먼저) ✅ 통과 보고 (2026-08-13 사용자)

기존 v1 방식이 그대로 동작하는지 확인한다. 여기가 실패하면 환경 문제부터 의심.

> **결과**: 통과 — v1 흐름(스캔→연결→읽기→레인징)으로 거리 표시 확인. 최초 시도 실패는
> 환경 원인(v1 앱 동시 설치/모드 영속화 잔존 추정)이었고 코드 회귀 아님 (모드 1 경로
> diff 0줄 재확인). 조정자 리팩터(002 T101) 빌드에서의 확인이므로 T102 의 모드 1 몫도
> 겸한다. 완료 판정은 checker 몫 (P11).
> **교훈**: 테스트 전 v1 앱("UWB Controlee") 강제종료/삭제 + 폰 모드 드롭다운이 1 인지 확인.

- 설정: 콘솔 = **스캐너 (v1)**, 폰 = **모드 1**. 보드 USB 연결·권한 허용.
- 절차: ① 폰 Start (광고 시작) ② 콘솔 [OOB] → 기기 목록에 폰 표시 → 선택·연결
  ③ 주소·세션 ID 자동 반영 ④ 자동 레인징 → 양쪽에 거리 표시.
- **통과**: v1 과 동일한 흐름(스캔→연결→읽기→레인징)으로 거리가 나온다.
- 실패 시: 콘솔·폰 모두 v1 대비 이 경로의 변경은 모드 분기 도입뿐 —
  로그 전문을 기록하고 §5 로.

### 검수 14 잔여 — 폰 광고 프레임 실측 (nRF Connect)

제3의 폰(또는 폰 ②)에 nRF Connect 설치 후 진행. 콘솔 앱 불필요.

- 절차: 폰 ① 을 **모드 2** 로 Start → nRF Connect 스캔.
- **통과**: 광고에 Service Data UUID `5F1D0001` 이 있고, 데이터가
  `01` + 폰 주소 2B + 세션 ID 4B (예: 세션 42 면 마지막 4B 가 `2A 00 00 00`) 로 보인다.
- ⚠ 마지막 4B 가 `00 00 00 2A` 로 보이면 **엔디언 버그** — 그대로 캡처해 기록
  (이 도메인 최대 함정).

### 검수 10 — 모드 2 E2E (비컨: 폰 광고 → 콘솔 관찰)

연결 없이 광고만으로 주소가 넘어가는지 확인한다.

- 설정: 콘솔 = **비컨 관찰**, 폰 = **모드 2**.
- 절차: ① **콘솔 [OOB] 먼저** (관찰 시작) ② 폰 Start.
  ⚠ 순서를 반대로 하면 폰 세션이 10초 만에 자동 종료될 수 있다 — 광고는 유지되므로
  폰 재Start 하면 정상 복구된다 (버그 아님).
- **통과**: 폰 Start 후 **3초 이내** 콘솔에 폰 주소 자동 반영 + 자동 레인징 + 거리.
  콘솔 로그 체인: `광고 관찰 시작` → `광고 수신 확정` → `OOB_INFO 수신(광고)` →
  `폰 주소 자동 반영` → `자동 시작: 준비 완료`.
- 추가 확인 (주소 재발급, §7-15): 폰 Stop → 재Start (새 주소) → 콘솔에
  `광고 내용 변경 감지 … 재전달` 로그 + 새 주소 반영.

### 검수 12 — 모드 3 E2E (광고 역전 + 병행 송출)

콘솔이 광고하고 폰이 받되, 폰도 자기 주소를 광고로 되돌려주는 **양방향**이 핵심이다.

- 설정: 콘솔 = **광고 송출** (광고 권한 팝업 허용), 폰 = **모드 3**.
- 절차: ① 콘솔 [OOB] (송출+관찰 시작) ② 폰 Start.
- **통과 — 4단계를 모두 확인**:
  1. 콘솔 로그 `ADV_INFO 광고 송출 시작`
  2. 폰 입력칸에 보드 MAC·세션 ID 자동 반영 (폰 화면 "🔵 광고 수신됨")
  3. **콘솔 로그 `폰 주소 자동 반영` + 자동 레인징 시작** ← 병행 송출의 핵심.
     이게 없으면 폰이 되돌려주는 광고를 콘솔이 못 받은 것
  4. 양쪽 거리 표시
- ⚠ 일부 칩셋은 송출+관찰 동시 동작 제약이 있다. 콘솔 로그에
  `광고 송출 실패 (code=…)` 가 뜨면: **code 숫자를 반드시 기록**하고, 관찰과 수동
  입력이 여전히 동작하는지 확인 (동작해야 정상 — 폴백 설계).

### 검수 13 — 짝 불일치 (오류 처리)

일부러 잘못된 조합으로 두고, 조용히 실패하지 않고 안내가 뜨는지 확인한다.

- 설정 예: 콘솔 = **비컨 관찰**, 폰 = **모드 1** (짝이 아님).
- 절차: 콘솔 [OOB] → 폰 Start → 10초 대기.
- **통과**: 양쪽 모두 크래시 없음 + 콘솔에 `광고 없음 — … 모드가 짝인지 확인` 안내 +
  타임라인이 성공으로 넘어가지 **않음** + 폰은 30초 후 수동 입력 폴백.
  이후 양쪽 모드를 짝으로 되돌리면 정상 동작해야 한다.

## 5. 실패 시 — 무엇을 남기나

원인 분석은 하지 않아도 된다. 아래만 남기면 개발 세션이 재현·추적 가능하다:

1. 어떤 검수, 어떤 단계에서 멈췄나 (예: "검수 12 의 3단계 — 콘솔에 폰 주소 안 뜸")
2. **양쪽 로그 창 전문** (스크린샷 또는 복사) — 특히 `[OOB]` 줄과 `code=`/`raw:` 숫자
3. 기기 기종·Android 버전 (칩셋 제약 판단용)
4. nRF Connect 로 광고가 실제 있는지 확인한 결과 (있음/없음)

자주 나오는 증상:

| 증상 | 1차 확인 |
|---|---|
| `광고 없음 — … 짝인지 확인` | 양쪽 모드가 §0 표의 짝인지 → 폰이 Start 상태인지 → nRF 로 광고 존재 확인 |
| `광고 송출 실패 (code=…)` | 칩셋 제약 가능성 — code 기록, 수동 폴백 동작 확인 |
| `파싱 실패: … (raw: …)` | raw hex 를 그대로 기록 (사양서 §4 대조는 개발 몫) |
| 주소는 반영되는데 거리 0건 | 무증상 파라미터 불일치 — 로그 전문 기록 후 개발 세션에 |
| BLE 실패가 수동 입력까지 막음 | **그 자체가 버그** — 즉시 기록 (BLE 는 부가 경로 원칙) |
