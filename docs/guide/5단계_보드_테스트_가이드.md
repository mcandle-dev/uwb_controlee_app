# 5단계 — DWM3001CDK ↔ Galaxy 실물 페어 테스트 가이드 (전달용)

- 작성일: 2026-07-04
- 목적: DWM3001CDK 보드(controller)와 Galaxy 폰(controlee 앱) 사이 FiRa UWB 레인징이
  실제로 되는지 확인하고, 결과를 아래 체크리스트에 기록해 회신한다.
- 소요 시간: 준비 ~30분 + 테스트 ~30분
- 이 문서만 보고 진행 가능하도록 작성함. 막히면 §6 트러블슈팅 → 그래도 안 되면
  체크리스트를 "실패 지점까지" 채워서 회신.

---

## 1. 준비물

- [ ] DWM3001CDK 보드 1개
- [ ] USB 케이블 (micro-USB) — 플래시용/통신용 (포트를 바꿔 꽂으므로 1개면 됨)
- [ ] UWB 지원 Galaxy 폰 (Note20 Ultra, S21+/Ultra 이상 플러스/울트라, Z Fold2 이후.
      **베이스/FE 모델은 UWB 없음**)
- [ ] Windows PC (Python 3.8 이상 설치)
- [ ] 테스트 앱 APK: `app-debug.apk` — 다운로드:
      https://github.com/mcandle-dev/uwb_controlee_app/releases/download/v0.1.0/app-debug.apk
      (또는 이 리포에서 `gradlew assembleDebug`로 직접 빌드)
- [ ] sasodoma/uwb-ranging 리포: https://github.com/sasodoma/uwb-ranging
      (`git clone` 또는 ZIP 다운로드)

## 2. 사전 준비 — PC

### 2-1. 보드 펌웨어 플래시

- [ ] 리포의 `new_firmware/DWM3001CDK-DW3_QM33_SDK_UCI-FreeRTOS.hex` 사용
      (⚠ **리포 동봉 사본** 사용. 다른 출처의 UCI 펌웨어는 스크립트와 버전이 안 맞을 수 있음)
- [ ] 보드의 **J-Link 라벨이 있는 USB 포트**에 케이블 연결
- [ ] 플래시 (둘 중 편한 방법):
  - 탐색기에 J-Link 이동식 드라이브가 뜨면 → hex 파일을 드래그&드롭
  - 또는 J-Flash Lite (SEGGER, 대상 nRF52833) → hex 선택 → Program
- [ ] 플래시 후 케이블을 **반대쪽 USB 포트**(보드 통신용)로 옮겨 꽂기

### 2-2. 파이썬 환경

```powershell
cd uwb-ranging\new_python_script
python -m venv venv          # (선택)
venv\Scripts\activate        # (선택)
pip install -r requirements.txt
```

- [ ] 설치 오류 없음
- [ ] 장치 관리자 → 포트(COM & LPT)에서 보드의 **COM 번호** 확인 (예 `COM5`) → 메모: ______

### 2-3. 폰 준비

- [ ] 설정 → 연결 → **UWB(초광대역) 토글 ON** (항목이 없으면 UWB 미지원/리전 비활성 기기 — 테스트 불가)
- [ ] `adb install -r app-debug.apk` (또는 전달받은 방법으로 설치)
- [ ] 앱 실행 → UWB 권한 **허용**
- [ ] 화면에 문제 배너(빨강/주황)가 **없고**, "내 UWB 주소"에 hex 값이 표시됨

## 3. 테스트 절차 (순서 엄수 — 앱 Start가 먼저)

1. [ ] 폰: 앱 실행. **내 UWB 주소** 확인 (예 `5F:DD`) → 메모: ______
   (탭하면 클립보드에 복사됨)
2. [ ] 폰: 입력값 확인 — 보드 MAC `00:00`, Session ID `42` (기본값 그대로)
3. [ ] 폰: **▶ Start** → 상태 배지가 파란 **WAITING**으로 바뀜
4. [ ] PC: 아래 명령 실행 (`COM5`와 `5F:DD`는 각자 값으로 교체):
   ```powershell
   python run_fira_twr.py -p COM5 --mac 00:00 --dest-mac 5F:DD -t -1
   ```
   콘솔에 세션 설정값 목록 + `Starting ranging...`이 출력됨
5. [ ] 관찰: **10초 내** 폰 배지가 초록 **RANGING**으로 바뀌고 거리(cm)가 갱신됨
6. 테스트 후 종료: PC에서 `<RETURN>` (스크립트 정지) → 폰 **■ Stop**

⚠ 주의사항:
- 테스트 내내 **앱을 전면(포그라운드)에 유지**. 백그라운드로 가면 세션이 자동 정지됨(정상 동작).
- 폰과 보드는 **30cm~2m, 장애물 없이** 시작할 것 (너무 붙이면 값이 튈 수 있음).
- Stop 후 재시작하면 폰 주소가 바뀔 수 있음 → 로그에 "내 주소 변경" 표시 →
  PC 명령의 `--dest-mac`도 새 주소로 바꿔서 재실행.

## 4. 검수 체크리스트 (결과 기록 — 이 표를 채워서 회신)

| # | 항목 | 방법 | 기대 결과 | 통과 | 실측/메모 |
|---|---|---|---|---|---|
| 5-1 | 세션 수립 | 절차 §3 그대로 | Start+스크립트 실행 후 10초 내 RANGING 전환, 거리 표시 | ☐ | 첫 거리: ___cm, 소요: ___초 |
| 5-2 | 거리 추세 | 보드를 폰에서 멀리(2~3m)/가까이(30cm) 이동 | 거리 값이 이동 방향대로 증감 | ☐ | 근거리 ___cm / 원거리 ___cm |
| 5-3 | 각도(azimuth) | 폰을 제자리에서 좌/우로 30° 이상 회전 | 각도 부호가 좌(-)/우(+)로 바뀜. 값이 아예 안 나오면 'N/A' 표시 | ☐ | 좌 ___° / 우 ___° (또는 N/A) |
| 5-4 | 수신없음 워치독 | PC 스크립트를 `<RETURN>`으로 정지 | **2초 내** 노란 "수신없음" 배지 (세션은 유지) | ☐ | |
| 5-5 | 피어 끊김 | 5-4 상태로 계속 방치 (또는 보드 USB 분리) | DISCONNECTED(빨강) 전환 + 로그 기록 (안 뜨고 수신없음 유지면 그대로 메모) | ☐ | 끊김까지 ___초 |
| 5-6 | 재시작 | 5-5 후 폰 Start → (주소 바뀌었으면 새 주소로) PC 재실행 | 다시 RANGING 진입 | ☐ | 주소 변경 여부: |
| 5-7 | 화면 회전 | RANGING 중 폰 가로↔세로 회전 | 세션 유지, 값 계속 갱신 (WAITING으로 돌아가면 실패) | ☐ | |
| 5-8 | 갱신 주기 | RANGING 중 "마지막 갱신" 표시 관찰 | 대략 0.1~0.3s 전 수준으로 계속 갱신 (120ms 주기) | ☐ | |
| 5-9 | 로그 확인 | 하단 로그 콘솔 | "첫 측정 수신", "측정 10건(avg …)" 요약이 쌓임 | ☐ | |

추가 기록 (선택):
- 폰 모델/One UI 버전: ______ / 측정 안정성(값 튐 정도) 체감: ______
- PC 스크립트 콘솔에 에러가 있었다면 그 출력 전체를 복사해서 첨부

## 5. 성공 판정

- **5-1, 5-2, 5-4, 5-6, 5-7 통과 = 브링업 성공.**
- 5-3(각도)은 기기·자세에 따라 N/A일 수 있음 — N/A 자체는 실패 아님 (단, 메모 필수).
  보드는 안테나 1개라 각도 검증은 폰 쪽 표시로만 한다.
- 5-5는 펌웨어에 따라 DISCONNECTED 통지가 안 올 수 있음 — "수신없음 유지"도 기록 가치 있음.

## 6. 트러블슈팅 (증상별 확인 순서)

### A. WAITING에서 멈추고 RANGING이 안 됨 (가장 흔함 — 대부분 파라미터/주소 불일치. 에러 없이 조용히 실패하는 게 이 도메인 특성)

확인 순서대로:
1. [ ] **순서**: 폰 Start가 먼저였나? (스크립트를 먼저 실행했다면: 스크립트 정지 → 폰 Stop → 폰 Start → 스크립트 재실행)
2. [ ] **주소**: `--dest-mac`이 폰 화면의 **현재** 주소와 같은가? (Stop/재시작 시 주소가 바뀜!)
3. [ ] `--mac 00:00`을 빠뜨리지 않았나? 폰의 보드 MAC 입력이 `00:00`인가?
4. [ ] Session ID: 폰 42 = 스크립트 기본 42 (스크립트에 `-s`를 따로 준 경우 일치 확인)
5. [ ] 스크립트가 **sasodoma 리포의 `new_python_script/run_fira_twr.py`** 인가?
      (원본 Qorvo SDK 스크립트는 slots/hopping 기본값이 달라 조용히 실패함)
6. [ ] 펌웨어가 리포 동봉 hex인가? (다른 UCI 펌웨어면 교체 후 재시도)
7. [ ] 거리 30cm~2m, 케이스/금속 없는 환경인가?
8. 위 전부 확인 후에도 실패 → 폰 로그 콘솔 캡처 + PC 콘솔 출력 복사해서 회신

### B. PC 스크립트가 에러로 죽음

- `session_set_app_config failed` → 펌웨어-스크립트 버전 불일치 가능성 큼.
  리포 동봉 펌웨어로 재플래시.
- 포트 오류(`could not open port`) → COM 번호 재확인, 다른 프로그램(터미널)이
  포트를 점유 중인지 확인, 케이블이 **통신용 포트**(J-Link 반대쪽)에 꽂혀 있는지 확인.
- `session_init failed` → 보드 리셋(케이블 재연결) 후 재시도.

### C. 앱에 문제 배너가 뜸

| 배너 | 조치 |
|---|---|
| "UWB를 지원하지 않습니다" | 기기가 UWB 미탑재 (베이스/FE 모델 등) — 다른 기기로 |
| "UWB(초광대역)를 켜세요" | 설정 → 연결 → UWB 토글 ON ([설정 열기] 버튼 사용) |
| "UWB 권한이 필요합니다" | [권한 요청] → 허용. 영구 거부했으면 [앱 설정]에서 수동 허용 |

### D. RANGING은 되는데 각도가 항상 N/A

- 실패 아님. 폰을 세로로 세우고(안테나 배치상 유리) 30cm 이상 거리에서 재시도.
  그래도 N/A면 해당 기종 특성으로 기록.
