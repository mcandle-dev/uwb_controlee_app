# 검수 10~13 — 폰·콘솔 함수 호출 맵 (디버깅용)

> 작성 2026-08-12. 실기기 검수 시 로그와 소스를 대조하기 위한 문서.
> 폰 = 이 리포 (`uwb_controlee_app`), 콘솔 = `uwb-console-kotlin` (읽기 전용 참조 — P13).
> 계약 원문: `docs/oob/BLE_OOB_인터페이스_사양서.md` v0.4.

## 0. 공통 구조

### 폰 쪽 파일
| 역할 | 파일 · 핵심 함수 |
|---|---|
| 조정자 (Start 분기·수명) | `MainViewModel.kt` — `startRanging()` 의 `when (state.oobMode)` |
| 모드 1 채널 | `uwb/OobGattServer.kt` — `open()/close()/updatePayload()` |
| 모드 2 채널 (+모드 3 병행 송출) | `uwb/OobBeacon.kt` — `open()/close()/updatePayload()` |
| 모드 3 채널 | `uwb/OobScanner.kt` — `open()/close()` + `onAdvertReceived` 콜백 |
| payload 빌드/파싱 | `uwb/UwbDefaults.kt` — `buildOobPayload()` / `parseOobPayload()` |
| 수신 판정 (순수) | `uwb/OobScanFilter.kt` — `evaluate()` |
| UWB 시작 공통 | `MainViewModel.beginPendingRanging()` → `collectRanging()` → `UwbRepository.rangingResults()` (prepareSession Flow) + `startWatchdog()` |

### 콘솔 쪽 파일
| 역할 | 파일 · 핵심 함수 |
|---|---|
| 조정자 | `ui/ConsoleViewModel.kt` — `startOob()` → `onScanResults()` → `onOobEvent()` → `onOobInfo()` → `tryOobAutoStart()` → `startRanging()` |
| 모드 1 채널 (GATT central) | `ble/AndroidBleOobChannel.kt` — `scan()/connect()/readOob()` |
| 모드 2·3 채널 (커넥션리스) | `ble/BeaconBleOobChannel.kt` — 같은 인터페이스(`BleOobChannel`)를 재매핑 구현 |
| 채널 선택 | `ble/BleChannelFactory.kt` — 설정(`AppSettings.BleMode`)에 따라 분기 |
| 자동 시작 게이트 | `ui/OobAutoStart.kt` — `OobAutoStartGate.request()/consumeIfReady()` |

**콘솔의 핵심 트릭**: 커넥션리스 모드에서도 UI/ViewModel 은 v1 과 같은 3단계 API
(`scan → connect → readOob`)만 본다. `BeaconBleOobChannel` 이 의미를 재매핑한다 (§6-1):
- `scan()` = 관찰 시작 (ADVERTISE 모드면 송출도 함께)
- `connect(p)` = **실제 연결 없음** — 광고 수신 확정을 `BLE_CONN` 이벤트로 재매핑
- `readOob()` = 마지막 수신 광고 payload 를 재방출

**콘솔의 OOB 공통 후반부** (모든 모드 동일):
```
onOobInfo(result)                              ConsoleViewModel
 ├ SessionID 불일치면 경고 로그
 ├ device.applyOobParams(uwbAddress, sessionId) — DST_MAC 반영
 ├ autoStartGate.request()
 └ tryOobAutoStart() → consumeIfReady(연결됨, SID일치, 미레인징)
      └ true → startRanging() → device.startRanging() (UCI SESSION_INIT…)
```

```
폰 (모드 1)                                     콘솔 (SCANNER)

  → 콘솔 `oobInfo` 재수신 → "주소 변경됨" 로그

## 검수 10 — 모드 2 (폰 BEACON 송출 ↔ 콘솔 BEACON 관찰)

**순서 중요: 콘솔 관찰을 먼저 시작** (폰이 UWB 를 즉시 시작하므로 — R1).

```
콘솔 (BEACON)                                   폰 (모드 2)
─────────────────────────────                  ─────────────────────────────
[OOB 시작]
ConsoleViewModel.startOob()
 └ BeaconBleOobChannel.scan()  (mode=BEACON)
    ├ startScan(LOW_LATENCY, 필터 없음
    │   — SW 필터: onScanResult 에서
    │   getServiceData(5F1D0001) null 이면 무시)
    └ OBSERVE_TIMEOUT 타이머 (무발견 시 안내)
                                                [Start 탭]
                                                MainViewModel.startRanging()
                                                 ├ RangingForegroundService.start()
                                                 ├ openOobBeacon(sessionId)
                                                 │  └ OobBeacon.open(payload)
                                                 │     └ startAdvertising()
                                                 │        (Service Data 5F1D0001 = 7B,
                                                 │         connectable=false, BALANCED)
                                                 └ beginPendingRanging(
                                                     "BEACON 모드 — 즉시 시작")
scanCallback.onScanResult
 └ onAdvert(result, data)
    ├ found 목록 갱신 → BLE_ADV 이벤트(첫 발견)
    └ scanResults 발행
       └ onScanResults() → connect(기기)
          └ BLE_CONN (수신 확정 재매핑, 연결 없음)
             └ onOobEvent → readOob()
                └ deliver(payload) → 파싱 → oobInfo
                   └ onOobInfo() → applyOobParams()
                      → tryOobAutoStart() → startRanging()
◀═══════════════ UWB DS-TWR 레인징 ═══════════════▶
```
- **3초 이내** 콘솔 주소 자동 반영이 통과 기준 (GATT 왕복 없음 — 사양서 검수 10)
- 갱신(§7-15): 폰 자동실패 → `endSession(keepOob)` → 주소 재발급 → `pushOobPayloadUpdate()`
  → `OobBeacon.updatePayload()` → `applyPayloadLocked()` (광고 stop→start 교체)
  → 콘솔 `onAdvert` 의 `changedForSelected` → `deliver()` 재전달 → "광고 내용 변경 감지" 로그
- R1 시나리오: 콘솔이 늦으면 폰 세션이 ~10초에 자동 종료(`onRangingFlowCompleted` → ERROR).
  광고는 유지되므로 콘솔이 주소 확보 후 폰 재Start.

## 검수 12 — 모드 3 (콘솔 ADVERTISE 송출+관찰 ↔ 폰 SCANNER 관찰+병행 송출)

```
콘솔 (ADVERTISE)                                폰 (모드 3)
─────────────────────────────                  ─────────────────────────────
[OOB 시작]
ConsoleViewModel.startOob()
 └ BeaconBleOobChannel.scan() (mode=ADVERTISE)
    ├ startAdvertise() ← §2-1 병행
    │   (Service Data 5F1D0003 =
    │    보드 MAC+SID 7B, connectable=false)

                                                 ├ openOobScanner()
                                                 │  └ OobScanner.open()
                                                 │     └ startScan(ServiceData 5F1D0003
                                                 │        빈값 매치 필터, LOW_LATENCY)
                                                 │        배지 ⚪ 스캔중
                                                 └ waitForOobAdvert() — 30s 타이머

                                                    │     Service Data 5F1D0001)
                                                    └ beginPendingRanging("콘솔 광고 수신")

    └ applyOobParams(폰 주소 = DST_MAC)  ← 병행안의 핵심

- 폰 폴백(§7-14): 30초 미수신 → `waitForOobAdvert` 타이머 → `beginPendingRanging("스캔 대기 시간 초과")` (수동 입력값)
- 콘솔 송출 실패(칩셋 제약 R2): `advertiseCallback.onStartFailure` → "폰이 콘솔을 발견할 수
  없습니다 … 수동 입력" 로그, **관찰은 계속** — 폰은 폴백 경로로 감
- 세션 중 콘솔 광고 변경: 폰 `onOobAdvertReceived` 가 `rangingJob != null` 이면
  "세션 중 변경 미지원, 재Start 필요" 로그만

## 검수 13 — 짝 불일치 (오류가 아니라 "발견 못함", §7-11)

| 조합 예 | 콘솔에서 일어나는 일 | 폰에서 일어나는 일 |
|---|---|---|
| 콘솔 BEACON ↔ 폰 모드 1 | 폰 광고에 Service Data 가 없어 `onScanResult` 의 `getServiceData()==null` → 전부 무시 → `OBSERVE_TIMEOUT_MS` 후 "광고 없음 — 양쪽 OOB 모드가 짝인지 확인" + `stopObserve()` | GATT 연결이 안 옴 → 30초 후 `waitForOobRead` → 수동 시작 |
| 콘솔 SCANNER ↔ 폰 모드 2 | 폰 광고가 connectable=false → v1 스캐너가 발견해도 연결 실패로 끝 (오동작 없음 — §5-2) | Read 가 없지만 모드 2 는 애초에 즉시 시작 — 영향 없음 |
| 콘솔 ADVERTISE ↔ 폰 모드 1·2 | 콘솔은 5F1D0001 을 관찰하므로 폰 모드 2 광고는 **수신됨** (부분 짝) — 단 폰이 5F1D0003 을 안 들으니 폰 입력칸 자동 반영은 없음 | 모드 1: 30초 폴백 / 모드 2: 정상 즉시 시작 |
| 아무 광고 없음 ↔ 폰 모드 3 | — | 30초 후 `콘솔 광고 미수신 — … (양쪽 모드가 짝인지 확인, §7-11/14)` 로그 + 수동 시작. 앱 크래시 없어야 통과 |

## 부록 — 자주 볼 로그 ↔ 함수 매핑 (폰)

| 로그 문구 | 발생 지점 |
|---|---|
| `OOB 광고 시작 (Service UUID …)` | `OobGattServer.advertiseCallback.onStartSuccess` (모드 1) |
| `BEACON 광고 시작 (Service Data …)` | `OobBeacon.advertiseCallback.onStartSuccess` (모드 2·3 병행·시뮬) |
| `SCANNER 시작 — 콘솔 광고(…) 관찰` | `OobScanner.startScan` |
| `콘솔 광고 수신 (MAC, rssi …)` | `OobScanner.handleScanResult` APPLY 분기 |
| `콘솔 광고 수신 — 보드 … 자동 반영` | `MainViewModel.onOobAdvertReceived` |
| `UWB 세션 시작 — <사유>` | `MainViewModel.beginPendingRanging` |
| `세션 종료 감지 — 유효 측정 0건 …` | `MainViewModel.onRangingFlowCompleted` (프레임워크 10초 자동 종료) |
| `OOB 유지 — 새 주소를 콘솔에 자동 전달 …` | `MainViewModel.endSession` keepOob 분기 (P7) |
| `BEACON payload 갱신 — 새 내용으로 광고 교체` | `OobBeacon.applyPayloadLocked` (§7-15) |
| `[시뮬] …` | `MainViewModel.consoleSimBeacon` (검수 12 테스트 보조 — 콘솔 있으면 불사용) |
