# UWB Controlee 테스트 앱 — 기능·화면 요구사항 정의서

- 작성일: 2026-07-03
- 대상: Android Galaxy (UWB 탑재 모델), Kotlin + Jetpack Compose + `androidx.core.uwb:uwb:1.0.0`
- 상대 기기: Qorvo DWM3001CDK (UCI 펌웨어, controller/initiator, PC의 `run_fira_twr.py`가 구동)
- 성격: 상용 앱이 아닌 **초도 기능 검증(Bring-up Test) 도구**. 화려함보다 진단 가능성이 우선.
- 기술 계약(세션 파라미터·코드 흐름·구현 순서)은 `../CLAUDE.md`가 기준. 이 문서는 그중
  **기능(FR)과 화면(UI)** 을 상세화한다. 두 문서가 충돌하면 CLAUDE.md가 우선.

---

## 1. 목적

DWM3001CDK 보드(controller)와 Galaxy 폰(controlee) 사이 FiRa UWB 레인징이 되는지를
**폰 쪽에서** 확인하고, 안 될 때 원인(권한/토글/파라미터/세션 순서)을 화면만 보고
좁힐 수 있게 한다. PC 쪽 레이더 콘솔(radar_test_console)과 짝을 이룬다.

## 2. 범위

**포함:** UWB 가용성 진단, controlee 세션 수립, 거리·각도 실시간 표시, 이벤트 로그.
**제외 (만들지 않는다):**
- BLE OOB 자동 교환 (주소는 수동 입력·수동 전달)
- 다중 피어, 백그라운드 레인징, 측정값 저장/내보내기
- controller 모드 (폰은 항상 controlee)
- 설정 화면/테마 옵션 등 부가 기능

## 3. 용어

| 용어 | 뜻 |
|---|---|
| Controlee | 레인징 응답자. 이 앱(폰)의 역할. 먼저 대기를 시작해야 한다 |
| Controller | 레인징 개시자. DWM3001CDK 보드 (PC 스크립트가 start) |
| 내 주소 | `sessionScope.localAddress`. PC 스크립트 `--dest-mac`에 입력할 값 |
| Static STS | 8바이트 세션 키 정보(Vendor ID 2B + IV 6B). 양쪽 동일해야 함 |

## 4. 기능 요구사항 (FR)

| ID | 이름 | 필수 | 설명 |
|---|---|---|---|
| FR-1 | UWB 가용성 진단 | 필 | 미탑재 / UWB 토글 OFF / 권한 거부 / 사용 가능, 4가지 상태를 **구분해** 표시하고 각각 해결 방법을 안내 |
| FR-2 | 런타임 권한 요청 | 필 | `UWB_RANGING` 권한을 첫 진입 시 요청. 거부 시 재요청 버튼 + 설정 이동 버튼 |
| FR-3 | 내 주소 표시 | 필 | controlee 세션 스코프에서 발급된 내 UWB 주소를 hex로 크게 표시. 탭하면 클립보드 복사 + 토스트 |
| FR-4 | 세션 설정 입력 | 필 | 보드 MAC(hex 2바이트, 예 `00:01`)과 Session ID(정수, 기본 42) 입력. 나머지 파라미터(채널 9/프리앰블 9/STS/Config)는 상수 — 화면에는 읽기 전용으로 표기만 |
| FR-5 | 레인징 시작/정지 | 필 | Start = controlee 대기 시작(Flow 수집), Stop = 취소. 입력값 검증 실패 시 시작 불가 + 사유 표시 |
| FR-6 | 실시간 측정 표시 | 필 | 거리(cm, m→cm 환산)·각도(azimuth °, null이면 'N/A')를 큰 숫자로. 갱신 시각 표시 |
| FR-7 | 상태 표시 | 필 | 대기중(IDLE) / 레인징 대기(WAITING: Start 후 첫 측정 전) / 레인징중(RANGING) / 피어 끊김(DISCONNECTED) / 오류(ERROR) |
| FR-8 | 무수신 워치독 | 필 | RANGING 중 2초간 측정 없으면 '수신없음' 표시 (세션은 유지) |
| FR-9 | 이벤트 로그 | 필 | 타임스탬프 + 이벤트 한 줄씩 스크롤 리스트. 측정은 10건마다 1줄로 요약(로그 폭주 방지). 최대 500줄 유지 |
| FR-10 | 절차 안내 | 필 | "① 앱 Start → ② PC에서 `run_fira_twr.py --dest-mac <내 주소>` 실행" 순서를 화면에 상시 안내 (controlee 먼저가 이 도메인의 함정이므로) |

### FR 상세 규칙

- **FR-3:** 주소는 세션 스코프 생성 시점에 발급되므로, 권한 획득 직후 자동으로 스코프를
  만들어 표시한다. Start 전에 사용자가 PC에 입력할 수 있어야 하기 때문.
  Stop 후 재시작 시 주소가 바뀔 수 있음 → 바뀌면 로그에 남기고 화면 갱신.
- **FR-4 검증:** MAC은 hex 2바이트 형식(`XX:XX` 또는 `XXXX`)만 허용. Session ID는 양의 정수.
  형식 오류 시 필드 아래 빨간 안내문, Start 버튼 비활성.
- **FR-5:** Start 후 세션 수립 실패(예외)는 ERROR 상태 + 예외 메시지를 로그에 원문 보존.
  앱은 절대 크래시하지 않는다.
- **FR-6 단위:** androidx는 거리를 **미터(Float)** 로 준다 → cm 정수로 환산 표시.
  거리 0~5000cm 밖이면 경고색(주황) 표시 (radar_test_console과 동일 규칙).
- **FR-8:** 워치독은 상태 배지만 바꾼다. 자동 재시작하지 않는다 (브링업 도구는 증상 보존이 중요).

## 5. 화면 요구사항

### 5.1 구성 — 단일 화면, 세로 스크롤 없이 한눈에

```
┌─────────────────────────────────────┐
│ ⚠ 상태 배너 (문제 있을 때만 노출)      │  ← FR-1/FR-2: "UWB 꺼짐 → 설정에서 켜세요" 등
├─────────────────────────────────────┤
│ 내 주소   [ 0A:3F ]  (탭=복사)        │  ← FR-3: 화면에서 가장 먼저 눈에 띄게
├─────────────────────────────────────┤
│ 보드 MAC [00:01]   Session ID [42]   │  ← FR-4: 입력 2개
│ CH 9 · PRE 9 · DS-TWR · STS 0807…   │  ← 고정 파라미터 읽기 전용 표기
├─────────────────────────────────────┤
│        [ ▶ Start ]  [ ■ Stop ]      │  ← FR-5: 상태에 따라 하나만 활성
│ ① 앱 Start → ② PC 스크립트 실행       │  ← FR-10: 순서 안내 (작은 글씨 상시)
├─────────────────────────────────────┤
│   ●RANGING     거리    각도          │
│               1 2 3 cm   -8°        │  ← FR-6/7: 표시 영역의 주인공, 큰 숫자
│   마지막 갱신: 0.3s 전                │
├─────────────────────────────────────┤
│ 12:00:01 세션 시작 (controlee 대기)   │
│ 12:00:04 첫 측정 수신                 │  ← FR-9: 로그 콘솔 (하단 고정 높이,
│ 12:00:14 측정 100건 (avg 118cm)      │     새 항목 시 자동 스크롤)
└─────────────────────────────────────┘
```

### 5.2 영역별 상세

**(A) 상태 배너** — 문제가 없으면 숨김. 상태별 문구·액션:
| 상태 | 문구 | 액션 버튼 |
|---|---|---|
| UWB 미탑재 | "이 기기는 UWB를 지원하지 않습니다" | 없음 (앱 기능 전체 비활성) |
| 토글 OFF | "설정 → 연결에서 UWB(초광대역)를 켜세요" | [설정 열기] |
| 권한 거부 | "UWB 권한이 필요합니다" | [권한 요청] / 영구거부 시 [앱 설정] |

**(B) 내 주소 카드** — 모노스페이스 큰 글씨. 주소 미발급 상태(권한 전)면 `--:--`.
탭 시 클립보드 복사 + "복사됨" 스낵바.

**(C) 설정 영역** — TextField 2개(보드 MAC, Session ID). 레인징 중에는 비활성(회색).
고정 파라미터 한 줄 표기는 보드 쪽과 눈으로 대조하는 용도 — 값은 `UwbDefaults.kt` 상수에서 가져온다.

**(D) 제어 + 절차 안내** — IDLE: Start만 활성. WAITING/RANGING: Stop만 활성.
ERROR/DISCONNECTED: Start 활성(재시도).

**(E) 측정 표시** — 화면에서 가장 큰 영역.
- 상태 배지 색: IDLE 회색 / WAITING 파랑(점멸 불필요) / RANGING 초록 / 수신없음 노랑 / DISCONNECTED·ERROR 빨강
- 거리: cm 정수, 범위 초과 시 주황. 측정 전에는 `---`
- 각도: 정수 ° (azimuth null이면 `N/A`). 부호 규칙: 좌측 음수 (androidx 규격 그대로)
- 마지막 갱신: "0.3s 전" 형식, 1초마다 갱신

**(F) 로그 콘솔** — 고정 높이(화면의 ~25%), 역순 아님(위→아래 시간순), 자동 스크롤.
로그 대상: 권한/가용성 변화, 주소 발급·변경, Start/Stop, 세션 예외(원문), 첫 측정,
이후 측정 10건마다 요약 1줄, 끊김, 수신없음 진입/해제.

### 5.3 상태 머신 (FR-7)

```
IDLE ──Start──▶ WAITING ──첫 측정──▶ RANGING ──2s 무수신──▶ RANGING(수신없음 배지)
  ▲                │                   │    ◀──측정 재개──────┘
  │                │                   ├─PeerDisconnected─▶ DISCONNECTED
  └──Stop/오류──────┴───────────────────┴─예외─▶ ERROR
(DISCONNECTED/ERROR에서 Start = 재시도, 새 세션)
```

## 6. 비기능 요구사항 (NFR)

| ID | 항목 | 기준 |
|---|---|---|
| NFR-1 | 표시 지연 | 측정 수신 → 화면 반영 100ms 이내 (Flow 수집 즉시 StateFlow 갱신) |
| NFR-2 | 안정성 | 어떤 UWB 예외에도 크래시 금지 — 잡아서 ERROR 상태 + 로그 |
| NFR-3 | 수명주기 | 화면 회전 시 세션 유지(ViewModel 소유). 앱 백그라운드 진입 시 세션 정지 + 로그 (백그라운드 레인징 미지원 명시) |
| NFR-4 | 종료 처리 | Stop/onCleared에서 Flow 취소로 세션 확실히 종료. 좀비 세션 금지 |
| NFR-5 | 로그 상한 | 로그 500줄 초과 시 앞에서 삭제 (메모리 무한 증가 금지) |

## 7. 검수 기준 (보드 없이 → 보드 확보 후 순)

**보드 없이 (에뮬레이터/실기기):**
1. UWB 없는 기기·에뮬레이터에서 "미지원" 배너가 뜨고 크래시 없음
2. UWB Galaxy에서 권한 플로우 → 내 주소가 hex로 표시되고 복사됨
3. MAC 형식 오류 입력 시 Start 비활성 + 안내문
4. Start → WAITING 상태 전환, Stop → IDLE 복귀, 로그에 기록

**보드 확보 후:**
5. 앱 Start → PC `run_fira_twr.py --dest-mac <내 주소>` → 10초 내 RANGING 전환, 거리 표시
6. 보드를 멀리/가까이 → 거리 값이 추세대로 변함, 폰을 좌우로 틀면 azimuth 부호 변함
7. PC 스크립트 중단 → 2초 내 '수신없음' → PeerDisconnected 시 DISCONNECTED + 로그
8. 레인징 중 화면 회전 → 세션 유지, 값 계속 갱신
