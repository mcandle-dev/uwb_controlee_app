# 4단계 — 세션 파라미터 쌍 대조 결과 (sasodoma/uwb-ranging)

- 작성일: 2026-07-04
- 기준 리포: https://github.com/sasodoma/uwb-ranging @ `aad72a0` (2025-05-28)
  - 앱 쪽: `android_app/app/src/main/java/eu/sasodoma/dwm3001cdkranging/UWBRanging.kt`
  - PC 쪽: `new_python_script/run_fira_twr.py` (Qorvo DW3_QM33_SDK 1.0.2 사본,
    **기본값이 이미 Android 프로필에 맞게 수정돼 있음** — README 참조)
  - 펌웨어: `new_firmware/DWM3001CDK-DW3_QM33_SDK_UCI-FreeRTOS.hex` (리포 동봉 사본 사용 권장)
- 보드 없이 코드 리뷰 수준으로 수행. 실측 검증은 5단계.

## 결론 (이번에 고친 것)

| 항목 | 대조 전 (placeholder) | 대조 후 (기준값) |
|---|---|---|
| Static STS 키 | `08 07 06 05 04 03 02 01` | **`08 07 01 02 03 04 05 06`** |
| 갱신 주기 | `RANGING_UPDATE_RATE_AUTOMATIC` | **`RANGING_UPDATE_RATE_FREQUENT`** (= 120ms) |
| 보드 MAC 기본값 | `00:01` | **`00:00`** (PC `--mac 00:00`과 쌍) |

STS IV의 바이트 순서가 함정이었다: PC 쪽 UCI 파라미터는 **리틀엔디언 정수**로 받으므로
`STATIC_STS_IV 0x060504030201`이 와이어에서는 `01 02 03 04 05 06`이 된다.
androidx `sessionKeyInfo`는 바이트 배열 그대로이므로 `08 07` + `01..06` 순서로 넣어야 일치.

## 전체 대조표 (앱 ↔ PC 스크립트 기본 실행 기준)

PC 실행 명령 (controller, 기본 프로필):
```
python run_fira_twr.py -p <COMx> --mac 00:00 --dest-mac <폰 주소> -t -1
```

| 파라미터 | 앱 (androidx.core.uwb) | PC (run_fira_twr.py 기본값) | 일치 |
|---|---|---|---|
| 역할 | controlee (`controleeSessionScope`) | controller/initiator (`DEVICE_TYPE=1, ROLE=1`) | ✓ (상보) |
| Config | `CONFIG_UNICAST_DS_TWR` | `RANGING_ROUND_USAGE=ds-deferred(2)` + `MULTI_NODE_MODE=unicast(0)` + `RFRAME_CONFIG=sp3(3)` + `SCHEDULE_MODE=time(1)` | ✓ |
| Session ID | 42 (UI 변경 가능) | `-s 42` 기본 | ✓ |
| 채널 | `UwbComplexChannel(9, …)` | `CHANNEL_NUMBER=9` | ✓ |
| 프리앰블 | `UwbComplexChannel(…, 9)` | `PREAMBLE_CODE_INDEX=9` | ✓ |
| STS 방식 | Static STS (config 내장) | `STS_CONFIG=static(0)` | ✓ |
| STS 키 | `sessionKeyInfo = 08 07 01 02 03 04 05 06` | `VENDOR_ID=0x0708` + `STATIC_STS_IV=0x060504030201` (LE) | ✓ (수정 후) |
| 레인징 주기 | `FREQUENT` = 120ms | `RANGING_DURATION=120` | ✓ (수정 후) |
| Sub-session | subSessionId=0, key=null | 미설정 | ✓ |
| 내 주소 | `localAddress` 자동 발급 → PC에 전달 | `DST_MAC_ADDRESS=[--dest-mac]` | ✓ (수동 전달) |
| 상대 주소 | UI 입력 (기본 `00:00`) | `DEVICE_MAC_ADDRESS=--mac` (기본 0x0) | ✓ |

### 앱에서 설정 불가능하지만 프로필에 함께 묶여 있는 값 (PC 기본값이 이미 맞춰져 있음)

androidx 1.0.0은 아래 값을 노출하지 않는다. `CONFIG_UNICAST_DS_TWR`+`FREQUENT` 프로필의
암묵값이며, sasodoma가 PC 스크립트 기본값을 여기에 맞춰 수정해 두었다
(원본 Qorvo 스크립트와 다른 부분 — README의 수정 목록):

| 파라미터 | PC 기본값 (수정본) | 비고 |
|---|---|---|
| `SLOTS_PER_RR` | 6 | 원본은 25 |
| `HOPPING_MODE` | enabled(1) | 원본은 disabled |
| `RSSI_REPORTING` | 1 | 원본은 0 |
| `SLOT_DURATION` | 2400 RSTU (2ms) | 원본과 동일 |
| `SFD_ID` | 2 | 〃 |
| `STS_LENGTH` | 1 (64심볼) | 〃 |
| `AOA_RESULT_REQ` | all-enabled(1) | 보드는 안테나 1개라 각도는 폰 쪽만 유효 |

→ **원본 Qorvo SDK 스크립트가 아니라 반드시 sasodoma 리포의 사본을 쓸 것.**

## 주소 바이트 순서 메모 (5단계 트러블슈팅 대비)

- 앱: `UwbAddress(byteArrayOf(0x00, 0x01))` — 입력 문자열 `"00:01"` 그대로.
- PC 수정본: `"XX:YY"` 입력을 `int("YYXX",16)`으로 뒤집어 UCI(LE)에 전달 —
  결과적으로 **양쪽 다 "화면에 보이는 문자열"이 같으면 일치**하도록 맞춰져 있다.
- 5단계에서 세션은 붙는데 측정이 안 나오면 제일 먼저 의심할 곳: 주소/STS 바이트 순서.

## 5단계 실행 절차 (보드 확보 후)

1. 보드에 `new_firmware/DWM3001CDK-DW3_QM33_SDK_UCI-FreeRTOS.hex` 플래시 (J-Link)
2. 앱 실행 → 내 주소 확인 (예 `5F:DD`) → 보드 MAC `00:00`, Session ID 42 확인 → **Start**
3. PC: `python run_fira_twr.py -p <COMx> --mac 00:00 --dest-mac 5F:DD -t -1`
4. 10초 내 RANGING 전환·거리 표시 확인 (검수 기준 5~8)
   - 주의: sasodoma README는 신펌웨어에선 폰 Start가 스크립트 실행 뒤여도 동작한다고 하나,
     검증된 순서(앱 먼저)를 기본으로 한다.
