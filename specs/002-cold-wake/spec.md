# 002 — 콜드 웨이크: 백그라운드 비콘 수신 → 자동 레인징 시작

작성일 2026-08-12. 사용자 요청(대화)으로 신설 — spec 001 범위 밖 (001 은 포그라운드 Start 전제).

입력: 사용자 확정 2026-08-12 — ① 구현 수준 = **콜드 웨이크** (앱 미실행 상태에서 OS 가 깨움),
② 사양서 §2-1 = **병행 송출** (T002 — 001 쪽에 기록). 실패 시 대기(Arm) 방식 후퇴 전제.

## 목적

폰이 앱 미실행/백그라운드 상태에서 콘솔의 ADV_INFO 비콘(`5F1D0003`)을 받으면 **스스로 깨어나
모드 3 시퀀스(수신 반영 → 병행 송출 → UWB 레인징)로 전환**한다. "폰은 비콘을 받아서
백그라운드에서 스캔(모드 3)으로 전환하는 역할" — 사용자 정의 그대로.

## 범위

### 포함
- "자동 감시" 토글 (메인 화면) — ON 시 PendingIntent 기반 BLE 스캔을 OS 에 등록, OFF 시 해제
- 비콘 수신 BroadcastReceiver → FGS 기동 → 모드 3 자동 Start (화면 없이)
- FGS 기동 실패(백그라운드 시작 제한) 시 고우선 알림 폴백 — 탭하면 앱 열리며 Start

### 제외
- 콘솔 쪽 변경 (기존 ADVERTISE 모드 광고가 그대로 트리거 — **OOB 계약 무변경**, 사양서 개정 불요)
- 부팅 시 자동 재등록(BOOT_COMPLETED) — 후속
- 보안 (평문 — 브링업 도구)

## 계약 요점

- 트리거 = 사양서 v0.3 §5-2 의 콘솔 광고 그대로. UUID·payload 신규 없음 (P5 절차 불필요)
- 깨어난 뒤의 동작 = spec 001 모드 3 시퀀스 재사용 (§2-1 병행 송출 포함)

## 수용 기준

1. 토글 ON → 앱 태스크 스와이프 제거 + 화면 OFF 상태에서 콘솔 광고 시작 → 폰이 FGS 알림을
   띄우고 레인징이 자동 시작된다 `[needs-device]`
2. FGS 백그라운드 시작이 거부되는 기기/상황에서는 고우선 알림이 뜨고, 탭하면 포그라운드
   Start 로 이어진다 (자동 실패가 기능 전체를 막지 않음 — P6 의 정신)
3. 토글 OFF 시 등록이 해제되어 더 이상 깨어나지 않는다
4. spec 001 의 3모드 수동 흐름에 회귀가 없다 (토글 기본값 OFF)
5. BLE/알림 권한 거부 시 토글이 비활성 + 안내 (UWB 수동 흐름 무영향 — P6)

## 미해결 / 전제 리스크 (plan 참조)

- **⚠ 방향 재검토 대기 (2026-08-12 논의)**: iOS 를 지원 범위에 넣으면 이 spec 의 전제
  (Android PendingIntent 스캔)가 성립하지 않는다 — iOS 는 현재 광고 포맷(Service UUID 목록
  AD 부재)으로 백그라운드 매치가 불가능하고, 폰이 payload 를 송출할 수도 없다.
  대안으로 **모드 4(GATT 역방향: 콘솔=peripheral, 폰=central+Write)** 가 도출됐고,
  채택하면 Android·iOS 를 한 경로로 통합할 수 있다 (계약 변경 수반 — P5/P13).
  근거·설계·바이트 계산: `docs/guide/ble_dev_guide.md` **§5·§7**.
  **아직 결정되지 않았다** — 코드 0줄인 지금이 방향을 바꾸기에 가장 싼 시점이므로,
  G1 승인 전에 "iOS 지원 여부"를 먼저 정한다.

- **백그라운드 FGS 시작 예외**(BLUETOOTH_SCAN 결과 수신 시 허용— Android 12+ 예외 목록)가
  Galaxy 에서 실제로 적용되는지 — 콜드 웨이크의 성립 조건. `[needs-device]` 로 최우선 확인.
  불성립 시 대기(Arm) 방식(상시 FGS)으로 후퇴한다 (사용자 합의).
- Galaxy "잠자는 앱"/Doze 에서 PendingIntent 스캔의 생존·지연.
- 조정 로직 소유권 이동 (plan D2 — 착수 게이트).
